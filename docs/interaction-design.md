# Респейс: быстрые практики и правила взаимодействия

Версия 0.2, 13 октября 2026 года. Содержательная спецификация до кода. Курс описан в [сценариях](lesson-scenarios.md) и [продолжении](lesson-scenarios-extended.md). Игровой досуг и научпоп — в [отдельном документе](play-and-pop-science.md).

## 1. Пространства приложения

| Пространство | Входной запрос | Что происходит |
|---|---|---|
| Разобраться | Хочу освоить навык | Карта из 12 коротких уроков |
| Сейчас | Хочу небольшой подходящий шаг | Короткие добровольные практики |
| Поиграть | Хочется приятного занятия | Конструктор, рисунки, небольшие истории |
| Любопытно | Хочу узнать что-то интересное | Научпоп-карточки и демонстрации |
| Моё | Хочу вернуться к своему | Личные заметки, меню отдыха, избранное, настройки |

Пользователь может сразу открыть любой раздел. Завершённый курс, дневник и определённое состояние не являются условием доступа к развлечениям.

## 2. Быстрые практики: проектная длительность около минуты

Время ниже — ориентир дизайна, а не исследованная лечебная доза. Практики основаны на авторских игровых примерах и общих навыках работы с вниманием, мыслями и выбором. [Руководство ВОЗ](https://www.who.int/thailand/activities/doing-what-matters-in-times-of-stress) описывает навыки управления стрессом; оно не проверяет наши сценарии игрового FOMO.

### «Боюсь упустить событие»

1. **Что происходит?** Название события по желанию, либо «просто подумать».
2. **Что известно?** «Награда исчезнет / потеряется возможность участия / пока не знаю / другое». Варианты отражают реальную неопределённость.
3. **Что это значит для меня?** Один добровольный вопрос о ценности награды и цене участия.
4. **Что выбираю сейчас?** Участвовать / сократить участие / пропустить / отложить решение / свой вариант.
5. **Выход.** «Вы рассмотрели несколько сторон решения». Можно сохранить собственную фразу, закончить или открыть соответствующий урок.

Ни один выбор не объявляется преодолением FOMO. Не предлагается компенсировать пропуск покупкой внутриигровых предметов.

### «После матча всё ещё кипит»

1. **Вход.** «Можно попробовать переключить внимание. Что удобнее?»
2. **Выбор.** Осмотреться / сделать обычное небольшое действие / закончить.
3. **Осмотреться.** Найти два внешних предмета; звук или опора тела — по желанию. Обычное действие: вода, окно, смена положения, свой вариант.
4. **Следующее действие.** Отдохнуть / поговорить / вернуться к игре / другое / пока не выбирать.
5. **Выход.** «Подходит / не подходит / не знаю» — необязательная отметка.

Дыхательные задержки, требование закрыть глаза и оценка степени спокойствия не включаются. Если неприятно, доступен немедленный выход и другой способ поддержки.

### «Устал после игры или работы»

1. **Один вопрос.** «Чего сейчас хотелось бы больше: тишины, общения, движения, простого приятного занятия или пока непонятно?»
2. **Два-три варианта.** Предложения из личного меню; при его отсутствии — простые примеры и собственный вариант.
3. **Проверка доступности.** «Это удобно сейчас?» Ответы да / изменить / ничего не выбирать.
4. **Выход.** Можно закрыть приложение и попробовать действие; возвращаться с отчётом не требуется.

Усталость не определяет автоматически выгорание. Предложения не устанавливают медицинскую пригодность физической нагрузки.

### «Не хочу подвести команду»

1. **Запрос.** Пропустить / уменьшить участие / уточнить расписание / другое.
2. **Заготовка.** «Мне важно ___; сейчас могу ___; для вашего плана сообщаю ___».
3. **Редактирование.** Можно сократить текст, убрать личные подробности, добавить признание конкретной договорённости.
4. **Выход.** Сохранить для себя / скопировать по нажатию / закончить.

Сообщение не отправляется автоматически. Уместность и безопасность разговора остаются предметом решения пользователя.

### «Открываю игру автоматически»

1. **Замечание.** «Что произошло непосредственно перед этим?» Необязательный ответ.
2. **Цель.** «Чего вы хотите сейчас?» Карточки с несколькими вариантами и «не знаю».
3. **Выбор.** Оставить игру / выбрать другое действие / подумать позже.
4. **Свой ориентир.** «Если захочу, сначала могу ___». Можно пропустить.

Привычное действие не называется зависимостью. Не включается штраф за возвращение к прежнему режиму.

## 3. Прогресс и дружелюбный персонаж

Предлагаемый персонаж — небольшой проводник по пространству, внешний образ пока не утверждён. Возможный характер: любопытный, спокойный, с лёгким игровым юмором. Он не диагностирует состояние и не изображает потребность в заботе пользователя.

Примеры реплик:

- Перед уроком: «Посмотрим на одну ситуацию?»
- При затруднении: «Тут легко смешать факт и ожидание. Откроем подсказку?»
- При личном ответе: «Можно оставить это для себя».
- После перерыва: «Ваши заметки на месте».
- На выходе: «Можно закончить здесь».
- В развлечении: «Нравится эта расстановка? Можно оставить её как есть».

Постоянный прогресс: темы просмотрены, навык попробован на примере, собственная карточка сохранена. Эти отметки не обозначают достигнутый уровень психического здоровья. Пользователь может скрыть их.

Возможное украшение личного пространства — свободный выбор из доступного набора. В первой версии весь набор открыт. Пользователь может увлечённо заниматься конструктором без предварительного выполнения психологических заданий.

## 4. Типы интерактивов

| Тип | Для чего | Как дать обратную связь |
|---|---|---|
| Выбор нескольких карточек | Мотивы, варианты, наблюдения | Отражение выбора; если задача учебная — пояснение по сюжету |
| Сопоставление | Различение понятий | Ключ относится к формулировкам истории, доступна подсказка |
| Распределение по группам | Факт, мысль, чувство; ценность и затраты | Объяснение каждого элемента без оценки человека |
| Конструктор предложения | Граница, план, гибкая мысль | Проверка наличия выбранных смысловых частей; собственная версия допустима |
| Ветвящийся разговор | Последствия разных реплик | Сравнение ясности и возможных последствий; без обещания чужой реакции |
| Личная заметка | Свой опыт | Сохранение только по решению; текст не оценивается алгоритмом |
| Творческая игра | Свободный досуг | Видимый результат действия; без интерпретации личности |
| Научная демонстрация | Любопытство | Пояснение эффекта и границ; без объявления персонального теста |

Для карточек всегда есть нажатие и выбор из меню; перетаскивание — дополнительная возможность. Для звуков — отдельное включение. Для движения — отключение и статичная альтернатива. Мелкие действия не должны требовать быстроты реакции.

## 5. Сохранение данных

| Материал | Предлагаемое поведение |
|---|---|
| Место в уроке | Можно сохранять автоматически, заранее объяснив это |
| Личный текст | Явная кнопка «Сохранить для себя» |
| Отказ отвечать | Завершение без обязательной записи о причине |
| План эксперимента | Отдельное сохранение и необязательное напоминание |
| Результат практики | Ответ по желанию; отсутствие ответа не равняется отсутствию пользы |
| Рисунок или комната | Сохранение текущего состояния, экспорт по нажатию |
| Научпоп | Избранное; никакой обязательной истории чтения |
| Данные исследования | Отдельная процедура и согласие, без автоматического переноса дневника |

Личные тексты не публикуются, не используются для таргетинга и не передаются стороннему ИИ по умолчанию. Экспорт должен ясно показывать, что именно окажется в файле.

## 6. План проверки содержания

Первая сессия проверки: один учебный урок, одна быстрая практика, одно развлечение и одна научпоп-карточка. Последовательность чередуется между участниками, чтобы не смешивать усталость от порядка с неудобством раздела.

Наблюдать:

- Понимает ли человек, где обучение, где личный выбор и где развлечение.
- Может ли закончить, пропустить личный вопрос и найти сохранённый материал.
- Не выглядит ли персонаж назидательным или инфантильным.
- Не воспринимается ли урок как тест на зависимость.
- Удобно ли занятие после усталости, насколько доступно с телефона.
- Не создаёт ли интерфейс чувство обязанности или затруднение при выходе.
- Корректно ли человек пересказывает научный факт, включая основное ограничение.

Для каждого материала отмечать статус: редакционный черновик → экспертно просмотрен → проверен с пользователями → уточнён → готов для технической реализации. Все материалы этой версии находятся на первой ступени.

Звук и движение регулируются независимо. Правила и проверка описаны в [документе о звуке и движении](sound-and-motion.md).
