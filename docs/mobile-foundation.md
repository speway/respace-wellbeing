# Мобильная основа Респейса

14 октября 2026 года. Существующий сайт упаковывается в Capacitor 8.5.3. Android и iOS используют одну веб-сборку из `dist/`, с прежними гостевыми сохранениями. Новый сервер или база не создаются.

## Что подготовлено

- Идентификатор обеих платформ — `app.respace.wellbeing`, название — «Респейс», версия исходников — 0.1.0.
- Android: минимальный API 24, сборка и target API 36; Gradle wrapper 8.14.3, Android Gradle Plugin 8.13.0.
- iOS: минимум iOS 15; зависимости подключаются через Swift Package Manager.
- Установлены официальные плагины `@capacitor/app` 8.0.0 и `@capacitor/splash-screen` 8.0.0.
- Единая иконка Ри используется в PWA, Android launcher/adaptive icon и iOS AppIcon; iOS LaunchScreen показывает тот же знак на спокойном фоне, Android 12+ использует его как системную splash-иконку. Шаблонный знак Capacitor не используется.
- `src/native.ts` подключает кнопку «Назад» Android и закрывает заставку после появления первого локального экрана. Вход, сеть и облако не задерживают открытие игр. Повторная инициализация не добавляет ещё один обработчик.
- На iOS исчезновение заставки длится 180 мс; при reduced motion — сразу. Android запускается без дополнительного fade. Звук, push и фоновые процессы не добавляются.

Это исходники и подготовленный жизненный цикл. Приложение ещё не проверено на устройстве или симуляторе; готовый APK/IPA не заявляется.

Three.js используется в необязательных объёмных сценах комнаты, созвездия и учебного маршрута; общий модуль подгружается только после выбора, а привычный 2D-интерфейс остаётся рабочим без WebGL. Объёмная комната строится из текущей расстановки и существующего атласа Респейса, маршрут — из отмеченных тем, а небо — из сохранённых точек и линий. Сцены работают в том же WebView Capacitor, не меняют формат сохранений и не вращаются сами; поворот запускается жестом, стрелками или кнопкой. Код сцены отделён от основного чанка.

Локально проверены типы `src/native.ts`, плагины, XML нативных экранов, JSON asset catalog, размеры иконок и сборка разделённой Three.js-сцены. Эти проверки не заменяют нативную сборку и действия на телефоне.

## Подключение к экрану

После синхронного `render()` вызвать:

```ts
void initNative(() => {
  // Закрыть открытый диалог или перейти к предыдущему экрану.
  // true = действие выполнено; false = верхний экран, можно выйти.
  return handleAppBack();
}).catch(error => console.warn('Не удалось завершить нативный запуск.', error));
```

Обработчик принадлежит основному интерфейсу: он знает о незавершённой игре, диалоге и текущей странице. Нельзя возвращать `false`, когда требуется сохранить или закрыть игровой экран. В веб-версии `initNative` сразу завершается без обращения к плагинам и DOM.

## Поля экрана

В `index.html` уже есть `viewport-fit=cover`. Встроенный SystemBars настроен как `insetsHandling: native` с начальным `cover`: на старых Android WebView Capacitor добавляет нативные поля, на новых отдаёт корректные `env(safe-area-inset-*)`. iOS использует поля CSS, поэтому `contentInset` задан как `never`, чтобы избежать двойного отступа. Верхняя панель, диалоги, боковые границы и нижняя навигация должны учитывать эти `env`. Проверка вырезов, клавиатуры и поворота требует реального устройства или симулятора. Увеличение WebView разрешено.

## Обновление и запуск

Из корня проекта:

```powershell
pnpm install
pnpm test
pnpm mobile:sync
pnpm android
```

`mobile:sync` сначала выполняет TypeScript/Vite-сборку, затем копирует результат и регистрирует плагины в обеих платформах. Обновлять исходники через `cap sync` до завершённой веб-сборки нельзя. Отдельные нативные заставки и настройки сохраняются.

Для Android нужны Android Studio 2025.2.1+, SDK Platform 36 и совместимый JDK 21 (обычно включён в Android Studio). После установки и настройки SDK:

```powershell
pnpm android:debug
```

Команда обновит веб-сборку и выполнит `gradlew.bat assembleDebug`. При успешной сборке файл окажется в `android/app/build/outputs/apk/debug/app-debug.apk`. Этот путь описывает будущий результат команды; файла сейчас нет.

Для iOS открыть проект на Mac с Xcode 26+:

```sh
pnpm mobile:sync
pnpm ios
```

В Xcode выбрать Team и симулятор/устройство, дождаться разрешения SPM-зависимостей, выполнить Run. Сборка для App Store и подпись — отдельный этап.

## Облако и перенос записей

Нативный гость сохраняет прогресс в WebView устройства. Его данные автоматически не становятся сохранением браузера или другого телефона; резервную копию можно перенести через существующий JSON-экспорт/импорт. Личные записи и игровой результат остаются в прежней схеме данных.

Нативный облачный вход пока отключён в `src/account.ts`. Это фактическое ограничение, а не заглушка работающего сервиса:

- клиент использует относительный `/api` и `credentials: same-origin`;
- нативный origin — `capacitor://localhost` на iOS и `https://localhost` на Android, тогда как API опубликован на домене сайта;
- обработчик изменения прогресса принимает только Origin своего домена; отдельного CORS-контракта для WebView нет;
- cookie-сессия Better Auth проверена для веба/PWA, но поведение cross-origin cookies в нативных WebView не проверено.

Для следующего этапа потребуется явный HTTPS API endpoint, узкий список разрешённых origin, CORS/preflight для запросов с учётными данными, настройки trusted origins Better Auth и выбранный способ хранения нативной сессии. Затем проверяются вход, выход, изоляция двух аккаунтов, облачный конфликт и отзыв сессии на Android/iOS. Подмена production `server.url`, включение `allowMixedContent` или снятие Origin-проверки не решают этот этап. До его проверки облачный кабинет доступен в веб-версии/PWA, а нативная оболочка предлагает локального гостя.
