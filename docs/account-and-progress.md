# Личный кабинет и игра без регистрации

Решение для прототипа, 13 октября 2026 года. Первое посещение ведёт прямо к занятиям. Нет обязательной регистрации, ограничения числа игр или требования курса для открытия предметов.

## Текущий production-статус · 24 октября 2026 года

Гостевой профиль и локальные данные доступны в Git-подключённой production-публикации. Маршрут `/api/auth/ok` сейчас возвращает Vercel `500 FUNCTION_INVOCATION_FAILED`, а кабинет сообщает, что облако недоступно. В Vercel-проекте нет production-переменных, необходимых `server/auth.ts`; поэтому регистрация и синхронизация сейчас не должны заявляться как работающие. Данные гостя остаются на устройстве. Перенос двух секретных production-переменных из старого Vercel-проекта ожидает отдельного разрешения владельца.

## Пользовательские сценарии

| Сценарий | Поведение |
|---|---|
| Гость открывает сайт | Все занятия доступны, сохранения принадлежат текущему браузеру |
| Закрывает и возвращается | Восстанавливаются темы, избранное, комната, созвездие, история и сохранённые записи |
| Создаёт аккаунт или входит | Загружается его профиль; гостевая копия остаётся отдельно |
| Хочет перенести гостевой прогресс | Видит количество локальных и облачных сохранений, объединяет темы и избранное, выбирает источник рисунков |
| Хочет перенести личные записи | Выбирает отдельный флажок; без него дневник и ответы гостя остаются в гостевой копии |
| Продолжает на другом устройстве | После входа загружается сохранение аккаунта |
| Работает без сети | Локальная копия сохраняется; облачная ошибка не объявляется успешной синхронизацией |
| Два устройства изменили одну версию | Сервер возвращает конфликт; автоматическая перезапись останавливается до сравнения |
| Отключает личную синхронизацию | Следующее облачное сохранение удаляет личную часть; локальные записи остаются |
| Выходит | Открывается отдельный гостевой профиль; записи аккаунта не становятся гостевыми |
| Удаляет аккаунт | Требуются текущий пароль и подтверждение; облачная запись удаляется вместе с аккаунтом |

## Что именно переносится

По умолчанию: просмотренные темы и позиция в теме, избранные карточки, позиции предметов и палитра комнаты, точки и линии неба, маршрут истории. Эти данные тоже отражают использование сервиса, поэтому регистрация сопровождается объяснением хранения прогресса.

Отдельный выбор: дневник и субъективные оценки, заметки из практик, названия опор, личный ориентир, название созвездия. Они не используются для автоматического психологического профиля и не включаются автоматически в дипломное исследование.

Черновые ответы внутри незавершённого урока живут в памяти интерфейса; сохраняется позиция, а не личный текст. Завершение темы означает просмотр материала, а не клинический результат или освоенный навык. Экспорт JSON содержит личные тексты независимо от настройки облака; об этом сообщается пользователю.

## Технические границы

Сервер определяет владельца только из проверенной сессии Better Auth. Клиент не задаёт `user_id` для чтения или записи. SQL параметризован. Запись содержит номер версии; сохранение принимается, только если исходная версия совпадает. Вход ограничен по частоте, облачные ответы не кешируются, изменяющие запросы проверяют Origin.

Данные аккаунтов и гостя разделены локальными ключами. JSON проходит проверку допустимых полей, объёма и типов; старые гостевые файлы продолжают читаться. Повреждённые локальные данные не перезаписываются молча.

## Ограничения этой версии

Почта для восстановления и подтверждения email не настроена. Для демонстрации используются тестовые аккаунты; для открытого исследования потребуется отдельная процедура согласия, политика хранения и почтовое восстановление. Текущий production API недоступен; нативные исходники используют локального гостя.
